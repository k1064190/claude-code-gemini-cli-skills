Subagent Stdin Hang Fix

Why

Doctor Cho reported that the codex-subagent and antigravity-subagent (agy) skills "often don’t get the request through and seem to freeze." These skills were the only supported subagents since gemini is deprecated, so the stalls blocked real work.

What

  • stdin blocking (primary): codex exec "prompt" and agy -p "prompt" read stdin whenever it is a non-TTY. If the harness hands over an open pipe with no EOF, the call blocks forever. 2>/dev/null hid codex’s Reading additional input from stdin... line, making it look like a silent freeze. Confirmed by OpenAI codex issue #20919; the official workaround is < /dev/null, now added to every non-resume invocation.
  • 2>/dev/null black-holed errors: auth, rate-limit, and flag errors produced empty stdout with no diagnostics. Stderr is now captured to ERRLOG=$(mktemp) and surfaced on non-zero exit or empty stdout.
  • No hard timeout: the codex skill had none, so a slow high-effort run looked frozen. A timeout -k 10 <N> wrapper now sends SIGTERM at the cap and SIGKILL 10 seconds later, so a call cannot hang indefinitely (exit 124 = timed out, 137 = force-killed).
  • --full-auto deprecated in codex, replaced with --sandbox workspace-write.
  • agy’s -p flag without --dangerously-skip-permissions writes edits to a scratch sandbox (~/.gemini/antigravity-cli/scratch/) instead of the project — now documented so a "reported success but files unchanged" result is diagnosable.
  • The claim that codex exec resume allows no flags was wrong per resume --help (resume [OPTIONS] [SESSION_ID] [PROMPT]); corrected.

How

Investigated with the systematic-debugging skill (root cause before fix). Every claim was reproduced deterministically: an open-pipe stdin yields exit 124, < /dev/null yields exit 0, a bad flag yields captured stderr, and a timeout -k wrapper kills a SIGTERM-ignoring child at exit 137. The 40-minute agy hang was traced via /proc/<pid>/fd pipe-inode ownership to an agentic find grandchild holding the RESULT=$(…) pipe open. Findings were cross-checked against the official codex docs (developers.openai.com/codex) and the installed CLIs’ own --help output.

Code locations

  • codex-subagent/SKILL.md — new "Avoiding hangs and silent failures" section; steps 3–6, Quick Reference, and Error Handling updated; canonical safe-invocation block added.
  • antigravity-subagent/SKILL.md — new "Avoiding hangs and silent failures (read first)" section plus scratch-sandbox note; output-format, Mode 1, @-syntax, resume, parallel, and error-handling examples updated; file-redirect canonical block added.

Retrospective

Two pushbacks from Doctor Cho drove the key fixes: "even long reasoning can’t take 5 hours" led to a hard timeout -k bound, and "making agy traverse $HOME is nonsense" led to finding the real 40-minute-hang mechanism. Carry forward: for any subagent "it froze" report, check three things — blocked stdin, discarded stderr, and a lingering agentic grandchild holding a $(…) pipe past the timeout — and capture long agentic-CLI output to a file, not a command substitution.
