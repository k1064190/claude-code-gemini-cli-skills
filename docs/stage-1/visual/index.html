Stage 1

Eliminates the codex/agy subagent freeze class.

Subagent Stdin Hang Fix

Why

Doctor Cho reported that the codex-subagent and antigravity-subagent (agy) skills "often don’t get the request through and seem to freeze." These skills were the only supported subagents since gemini is deprecated, so the stalls blocked real work.

What

  1. stdin blocking (primary): codex exec "prompt" and agy -p "prompt" read stdin whenever it is a non-TTY; an open pipe with no EOF blocks forever, and 2>/dev/null hid the notice — a silent freeze. Confirmed by OpenAI codex issue #20919; official workaround < /dev/null added to every non-resume invocation.
  2. 2>/dev/null black-holed errors. Auth/rate-limit/flag errors produced empty stdout, no diagnostics. Now: capture stderr to ERRLOG=$(mktemp) and surface it on non-zero exit / empty stdout.
  3. No hard timeout. Added timeout -k 10 <N>: SIGTERM at the cap, SIGKILL 10s later; exit 124 = timed out, 137 = force-killed.
  4. --full-auto deprecated in codex — replaced with --sandbox workspace-write.
  5. agy -p without --dangerously-skip-permissions writes edits to a scratch sandbox (~/.gemini/antigravity-cli/scratch/), not the project — documented.
  6. codex exec resume flag claim ("no flags allowed") was wrong per resume --help — corrected.

How

Investigated with the systematic-debugging skill (root cause before fix). Every claim reproduced deterministically (open-pipe stdin → exit 124; < /dev/null → exit 0; bad flag → captured stderr; timeout -k kills a SIGTERM-ignoring child at exit 137). The agy 40-minute hang was traced via /proc/<pid>/fd pipe-inode ownership to an agentic find grandchild holding the RESULT=$(…) pipe open — fixed by capturing agy stdout to a file, never $(agy …), and by never making agy hunt for files. Cross-checked against official codex docs and the CLIs’ own --help.

Review loop

Three reviewers per CLAUDE.md: the code-reviewer-pro subagent, codex (GitHub bot on PR #3), and antigravity-subagent/agy.

  • Round 1 (code-reviewer-pro + codex): convergent findings fixed — an undefined $ERRLOG in inline snippets (verified as a hard bash failure), inconsistent stderr handling in the parallel block, a status variable colliding with fish/zsh’s read-only $status (renamed to rc), and a wrong "resume takes no flags" claim (corrected via resume --help). Codex’s P2 on parallel $ERRLOG was addressed by making each parallel call self-contained. Dismissed with evidence: a codex --add-dir P2 and a claim about resume’s stdin - handling, both disproven by targeted tests.
  • Round 2 (agy review): running agy on the diff surfaced two real defects — the positional resume --last form was missing < /dev/null, and resume examples still used 2>/dev/null against the new capture-stderr rule. Both fixed.
  • The big one — agy’s "review takes 40 minutes" hang: pointing agy at @final.diff from a scratch directory made its agent launch a full $HOME find to locate the file; timeout -k killed agy but not that grandchild, which kept a RESULT=$(…) pipe open for ~40 minutes (confirmed via /proc/<pid>/fd pipe-inode ownership). Fixed by capturing agy’s stdout to a file instead of command substitution, and by never making agy hunt for files.

Retrospective

Two user push-backs drove the most important fixes: "even long reasoning can’t take 5 hours" → hard timeout -k bound; "making agy traverse $HOME is nonsense" → found the 40-minute-hang mechanism (agentic find grandchild holding a command-substitution pipe). Carry forward: for any subagent "it froze" report check stdin blocking, discarded stderr, and a lingering grandchild holding a $(…) pipe; capture long agentic-CLI output to a file.
