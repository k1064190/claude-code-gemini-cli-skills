codex 기본 모델을 gpt-5.6-sol로 올립니다.

Codex Default Gpt 5.6 Sol

왜

OpenAI가 2026-07-09에 GPT-5.6 계열(등급: Sol 플래그십 / Terra / Luna)을 출시했습니다. 이 스킬은 기본 모델을 명시적으로 고정해 두는 방식이라(설계상 — 새 릴리스를 자동으로 추적하지 않음) 업데이트하기 전까지는 계속 gpt-5.5를 사용하고 있었습니다. Doctor Cho는 새 모델이 자동으로 반영되는지 물었고, 답은 "아니오"였습니다. 두 계층(스킬 기본값 + ~/.codex/config.toml) 모두에서 그랬고, 설치된 CLI(0.139.0) 버전도 해당 모델보다 이전 버전이었습니다.

무엇을

  • codex CLI를 0.139.0 → 0.144.1로 업그레이드했습니다 (codex update). 0.139.0은 해당 모델을 400 "requires a newer version of Codex" 오류로 거부했습니다.
  • ~/.codex/config.toml: model = "gpt-5.5" → "gpt-5.6-sol"로 변경했습니다.
  • codex-subagent/SKILL.md: 기본값을 gpt-5.6-sol로 변경했습니다(effort high는 그대로 유지). 모델 목록을 5.6의 세 등급으로 갱신했고, 표준 예제를 업데이트했으며, 두 가지 주의사항을 추가했습니다 — gpt-5.6 별칭을 단독으로 쓰지 말 것(ChatGPT 계정 인증에서 400 "not supported when using Codex with a ChatGPT account" 오류 발생), 그리고 "requires a newer version" 오류가 나면 codex update를 실행할 것.
  • 전략 결정(사용자): 선호했던 "별칭 반자동" 방식은 ChatGPT 계정 인증에서 실증적으로 막혀 있어서, 명시적인 gpt-5.6-sol 고정 방식으로 되돌아갔습니다. OpenAI가 ChatGPT 계정에 별칭을 허용하게 되면 재검토할 예정입니다.

어떻게

수정하기 전에 모든 주장을 실제 CLI로 검증했습니다. 별칭은 거부되었고(400), gpt-5.6-sol/-terra/-luna를 명시적으로 지정하면 모두 정상 동작했으며, effort high와 xhigh 모두 sol에서 유효했습니다. -m 없이 실행하면 갱신된 설정을 통해 sol로 해석되었습니다. 모든 테스트는 stage-1의 안전한 패턴(< /dev/null, $ERRLOG, timeout -k, 파일 리다이렉트)을 사용했습니다 — 별칭 실패는 조용한 멈춤이 아니라 즉시 명확한 400 오류로 나타나, stage-1 작업이 유효함을 검증해 주었습니다.
